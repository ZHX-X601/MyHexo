法宝AI法律助手全栈项目开发

一、项目概述

法宝是一个AI法律助手全栈项目，提供三大核心功能：AI法律咨询、法律文书生成、合同风险审查。

层 技术栈 端口
前端 Vue 3 + Vite + Vue Router 4 + Element Plus + axios 5173（dev）
后端 FastAPI + SQLAlchemy 2.0 + Pydantic V2 + JWT + python-docx 8000
AI引擎 FastGPT（本地部署，3个应用：法律咨询/文书起草/合同审查） 3000
数据库 MySQL 8.0（utf8mb4，5张表） 3306

设计语言：深蓝 #1a3a5c + 金色 #c9a96e，专业法律感。

2.5 页面动态展示机制（Vue Router驱动）

核心问题：App.vue怎么做到”动态展示其他页面”？

本项目不用数组 + activeIndex + 动态组件的手动写法，而是用Vue Router驱动：

页面切换的6步链路

步骤 发生什么 在哪个文件
1 点击导航或按钮 AppHeader.vue（router-link）/ HomePage.vue（router.push）
2 地址栏URL变化 浏览器
3 路由表匹配：path→component router/index.js
4 懒加载：首次访问才下载页面组件 router/index.js 的 () => import(...)
5 router-view拿到匹配的组件对象 App.vue 的 v-slot
6 transition + <component :is> 渲染新页面 App.vue

App.vue核心渲染结构

逐层拆解：

代码 作用
<router-view> 路由出口，自动拿到”当前URL匹配的组件”
v-slot="{ Component }" 作用域插槽，把匹配到的组件对象解构出来
<transition mode="out-in"> 切换动画：旧组件完全消失后新组件再进来
<component :is="Component" /> 动态组件，:is是哪个组件对象就渲染哪个

一句话：router-view负责”算出现在该显示谁”，component :is负责”把它画出来”。

URL切换底层机制

<router-link>渲染成<a href>，但点击时不是浏览器默认跳转，而是Vue Router接管：

关键：pushState只改地址栏、不发网络请求——这是SPA”切换页面但浏览器不刷新”的全部秘密。

currentRoute：URL与页面之间的桥

Vue Router内部有一个currentRoute响应式对象，<router-view>依赖它：

URL变了 → currentRoute.value更新 → 依赖它的计算属性失效 → router-view重渲染 → <component :is>实例化新组件

三条路径殊途同归：

路径 URL是谁改的 结果
点router-link / router.push() Vue Router用pushState主动改 地址栏变 + 组件切换，无刷新
浏览器前进/后退 浏览器改（触发popstate事件） Router监听后更新currentRoute → 组件切换
地址栏手输/F5刷新 浏览器整页加载 应用重启 → 路由读URL匹配渲染

状态驱动 vs URL驱动

维度 手动写法（状态驱动） 本项目（URL驱动）
切换”开关” 内存里activeIndex数字 地址栏URL字符串
浏览器前进/后退 不支持 原生支持
刷新页面 回到主页 停留在当前URL对应页面
组件加载 启动时全部import 路由懒加载，用到才下载
扩展性 加页面改多处 加路由+组件即可，App.vue不动

五、部署与联调

5.1 前后端两个”服务”的本质区别

前端 后端
技术 Vue 3 + Vite + Element Plus FastAPI + MySQL
本质 一堆静态文件（HTML+JS+CSS） 一个持续运行的程序，监听端口等请求
部署要求 任何能放静态文件的地方（CF Pages、Nginx、OSS） 必须有一台一直开着机的服务器跑它

npm run build后前端就是dist/目录里的一堆文件，没有”进程”概念。能”调接口”纯粹是因为浏览器执行了其中的JS代码发起HTTP请求。”前端部署在哪”和”后端部署在哪”完全独立，中间只靠一个URL连接。

5.2 请求从哪发出：http.js统一封装

  • 没设置VITE_API_BASE_URL（本地dev）→ baseURL = '/api/v1'，相对路径，请求发给当前页面所在服务器
  • 设置了（CF Pages）→ baseURL = 'https://954487onpr52.vicp.fun/api/v1'，绝对地址，直接打到花生壳

import.meta.env是编译时替换，不是运行时读取！Vite打包时直接把代码替换成字符串常量写死进JS。改环境变量后必须重新部署（重新build）才生效。

5.3 本地开发：Vite代理消跨域

工作流程：

为什么没有跨域？ 页面来自5173，请求也发给5173 → 同源 → 浏览器不干涉。Vite转给8000是服务器间通信，浏览器不知道。

⚠️ npm run dev有代理 ✅；npm run preview预览build产物不带proxy（那是另一套preview.proxy配置，本项目没配）。所以本地build完preview会连不上后端——proxy不进打包产物。

5.4 线上部署架构

  • 前端：CF Pages，自定义域名 https://fabao.blog-x.cc.cd
  • 后端：花生壳内网穿透 https://954487onpr52.vicp.fun
  • 前端生产构建：VITE_API_BASE_URL 环境变量拼完整后端地址（Vite proxy仅dev生效）

5.5 CF Pages 405错误：静态托管不认识POST

当前端没配VITE_API_BASE_URL时，baseURL是相对路径/api/v1，浏览器把请求发给CF Pages自己。CF Pages是静态文件托管，只会”找文件、发文件”，对/api/v1/auth/login这个路径发POST → 405 Method Not Allowed。

解法：CF Pages项目设置里加构建环境变量 VITE_API_BASE_URL = https://954487onpr52.vicp.fun，打包出的JS里baseURL变完整地址，请求直接发给花生壳。

格式三要求：https://开头、不带/api/v1（代码会自己拼）、末尾不带/。

5.6 花生壳：让家里电脑”被公网访问”

后端跑在家里127.0.0.1:8000，家里宽带通常没有公网IP。花生壳（内网穿透）解决：

  • 隧道是客户端主动向外建立的长连接，不需要公网IP、不需要端口映射
  • 前提：电脑开机 + 后端运行 + 花生壳客户端在线，三者缺一线上就挂
  • 免费版限制：带宽小、域名随机、有流量限额——演示够用，生产不行

5.7 CORS跨域：线上真正的”元凶”

同源策略

浏览器同源策略：协议 + 域名 + 端口三者完全一致才算同源。

页面地址 请求地址 是否跨域
http://localhost:5173 http://localhost:5173/api/... 否（走代理时）
https://fabao.blog-x.cc.cd https://954487onpr52.vicp.fun/api/... 是（域名不同）

跨域被拦的真实机制

跨域不是”请求发不出去”：

  1. 登录请求带Content-Type: application/json，属于非简单请求
  2. 浏览器先偷偷发OPTIONS预检请求（preflight），问后端：”我这个来源、方法和头，你允许吗？”
  3. 后端响应头必须带Access-Control-Allow-Origin: https://fabao.blog-x.cc.cd才算”批准”
  4. 预检通过 → 浏览器才发真正的POST；不通过 → 浏览器直接拦截，JS只收到无响应的错误

为什么本地开发从没遇到CORS？因为本地走Vite代理，请求对浏览器是同源，CORS机制根本没被触发。这是”本地没问题、一上线就出事”的根本原因。

后端CORS白名单

backend/.env：CORS_ORIGINS=["http://localhost:5173","http://localhost:5174","https://fabao.blog-x.cc.cd"]

修改后必须重启后端（--reload只监听.py文件，不监听.env）。

5.8 多实例”假重启”坑

改了.env也”重启”了，线上依然报跨域。原因：电脑上残留6个python进程（两组后端实例，uvicorn –reload启动=父进程+工作进程），占8000端口的实例仍用旧配置。

为什么会残留：Windows上点X关窗口或Ctrl+C偶尔杀不干净，进程变后台孤儿继续跑。

加固措施：

  1. app/config.py：读.env从相对路径改成绝对路径（避免从非backend目录启动读不到.env）
  2. app/main.py：启动日志打印CORS 允许来源：[...]——一眼看出配置有没有生效

需求 改哪里 改完必须做什么

前端请求的后端地址（线上） CF Pages环境变量VITE_API_BASE_URL 重新部署（重新构建才生效）

5.10 排错思路（前端连不上后端）

  1. 请求打到哪了？ → F12 Network看失败请求的URL → CF Pages自己域名说明VITE_API_BASE_URL没配/没重新部署
  2. 服务通不通？ → 浏览器开https://后端地址/docs或curl → 打不开=花生壳/后端没在跑
  3. 是不是跨域被拦？ → F12 Console看blocked by CORS policy，用OPTIONS curl验证
  4. 配置真的生效了吗？ → 看后端启动日志CORS 允许来源：[...]，还是旧值=有残留实例

六、问题与解决

问题1：FastGPT chatId硬编码导致跨用户记忆串台

  • 现象：zhang聊过”张三欠5000”，新对话和lisi账号都能”记得”并复述
  • 原因：ai_service.py 的 chatId: "fabao-backend" 是写死常量，所有用户共用一条FastGPT会话
  • 解决：chatId改为 fabao-chat-u{user_id}-c{conversation_id}，三模块统一前缀+用户+主键

问题2：文书下载丢失AI生成内容

  • 现象：下载的docx变成前端输入的表单值模板拼接
  • 原因：第一轮改造把 DownloadRequest 改成只收 form_data，AI内容被丢弃
  • 解决：保留AI内容走智能排版（format_ai_content_docx），form_data 仅作降级

问题3：python-docx中文变方块

  • 原因：只设了ascii字体族，未设eastAsia
  • 解决：每个run同时设置 font.name = "Times New Roman" + font._element.rPr.rFonts.set(qn('w:eastAsia'), 'Microsoft YaHei')

问题4：历史列表登录后显示”无历史”

  • 原因：onMounted 时未登录→loadSessions 直接return；登录后无重新触发
  • 解决：watch(isLoggedIn)，登录→重新加载，登出→清空列表

问题5：CORS 400 Disallowed CORS origin

  • 原因：改.env后有6个残留python进程，占用8000的实例仍是旧配置
  • 解决：杀干净全部残留进程 + .env 补线上域名 + 单实例重启

七、未解决的问题

  1. FastGPT旧记录：硬编码chatId产生的旧记录（含zhang隐私内容）需手动在FastGPT后台删除
  2. 对话删除不同步FastGPT：前端删对话只删MySQL，FastGPT侧chat记录残留（chatId唯一化后不再读写，无害但不干净）
  3. 合同审查记忆策略：同一合同重新审查共用chatId带历史，如需每次无记忆需加时间戳
  4. FastGPT使用者识别：后台”使用者”列全显示Owner（API Key属主），OpenAPI方式无法区分真实用户
